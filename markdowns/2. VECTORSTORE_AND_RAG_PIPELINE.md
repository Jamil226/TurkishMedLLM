# TurkishMedLLM: Vector Store & RAG Pipeline Documentation

Following the data preprocessing stage, the project transitioned into building the searchable knowledge base and the response generation system. This document covers Step 3 (Vector Store), Step 4 (Evaluation), and Step 5 (RAG).

---

## 1. Vector Store Construction (Step 3)
The goal of this stage is to convert processed text chunks into mathematical vectors that can be searched for similarity.

### Embedding Backend
- **Model**: **`bge-m3`** via Ollama. This model was selected for its state-of-the-art multilingual performance, specifically for Turkish medical terminology.
- **Dimensionality**: 1024.
- **Provider**: [Ollama](https://ollama.ai/) running locally to ensure data privacy.

### Vector Database
- **Provider**: **ChromaDB**.
- **Persistence**: Data is stored locally in `data-vectorstore/chroma/turkishmedllm_chroma_db`.
- **Indexing Strategy**: Chunks are processed in batches of 500 to optimize throughput and memory usage.

### Resilience and Resume Support
- **Progress Tracking**: A `vectorstore_progress.json` file tracks already-embedded chunk IDs.
- **Resume Capability**: If the indexing process is interrupted, it automatically detects processed IDs and continues only with the remaining delta, preventing duplicate embeddings and redundant API calls.

## 2. Retriever Evaluation (Step 4)
To ensure the quality of retrieved information, a dedicated evaluation module was developed.

### Test Query Suite
A collection of 15 targeted Turkish medical queries was created, covering:
- Disease symptoms (Diabetes, Hypertension, Stroke).
- Emergency procedures (Heart attack, Asthma attack).
- Patient safety (Antibiotic use, Pregnancy).

### Evaluation Metrics
Retrieval quality is measured using **Hit Rate @ K**:
- **Hit Rate @ 1**: ~93% (Top result is relevant).
- **Hit Rate @ 5**: 100% (A relevant result exists in the top 5).
- **Relevance Estimation**: An automated keyword-matching system classifies results as *Relevant*, *Partially Relevant*, or *Irrelevant*.

---

## 3. Basic RAG Pipeline Implementation (Step 5)
The Retrieval-Augmented Generation (RAG) system combines the retriever with a chat model to generate safe medical answers.

### Safety-Constrained Prompting
The RAG prompt includes strict clinical and safety constraints:
- **Groundedness**: Must use only the retrieved context.
- **Diagnosis Warning**: Prohibits definitive diagnosis; requires advising a doctor's visit.
- **Emergency Escalation**: Mandates mentioning emergency care for severe symptoms.
- **Accuracy**: Prohibits medication dosage advice unless explicitly supported by context.

### Indexing Progress Guard
To prevent inaccurate answers during the construction phase, the pipeline checks the vectorstore completeness:
- If less than 95% of the corpus is indexed, the system issues a warning.
- Requires an explicit `--allow_partial_index` flag to proceed during construction.
