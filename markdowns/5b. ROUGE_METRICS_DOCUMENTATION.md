## Overview

This document describes the comprehensive ROUGE metrics evaluation performed on the Turkish Medical LLM dataset across 5 training epochs. ROUGE metrics measure the overlap between generated text and reference text, providing quantitative assessment of model-generated medical content quality.

---

## ROUGE Metrics Explained

### ROUGE-1 (Unigram Overlap)
- **Measure:** Overlap of single words between hypothesis and reference
- **Use Case:** Captures basic word-level agreement
- **Formula:** F-score based on unigram precision and recall
- **Value Range:** 0.0 to 1.0 (1.0 = perfect match)

### ROUGE-2 (Bigram Overlap)
- **Measure:** Overlap of two-word sequences (bigrams)
- **Use Case:** Captures phrasal consistency and word ordering
- **Formula:** F-score based on bigram precision and recall
- **Value Range:** 0.0 to 1.0
- **Sensitivity:** More strict than ROUGE-1, detects phrase-level differences

### ROUGE-L (Longest Common Subsequence)
- **Measure:** Longest consecutive matching sequence between hypothesis and reference
- **Use Case:** Captures structural similarity independent of exact word position
- **Formula:** F-score based on LCS (Longest Common Subsequence)
- **Value Range:** 0.0 to 1.0
- **Advantage:** Captures sentence-level structure better than ROUGE-1/2

### ROUGE-Lsum (Longest Common Subsequence - Summary)
- **Measure:** ROUGE-L applied to entire document (multi-sentence)
- **Use Case:** Evaluates consistency across multiple sentences
- **Formula:** Average of ROUGE-L scores across document
- **Value Range:** 0.0 to 1.0
- **Application:** Best for longer medical text generation

## Generated CSV Files

### 1. Epoch-Specific Results (5 files)
**Files:** `rouge_metrics_epoch_1.csv` through `rouge_metrics_epoch_5.csv`

**Structure:**
```
- sample_id: Sample identifier (0-99)
- epoch: Training epoch number (1-5)
- instruction: First 100 characters of medical question
- reference_length: Word count of reference answer
- hypothesis_length: Word count of generated answer
- rouge1: ROUGE-1 F-score
- rouge2: ROUGE-2 F-score
- rougeL: ROUGE-L F-score
- rougeLsum: ROUGE-Lsum F-score
- timestamp: Evaluation timestamp
```

**Purpose:** Individual epoch-level performance tracking
**Size per file:** ~17KB
**Total samples per epoch:** 100

### 2. Metric-Specific Aggregates (4 files)
**Files:** 
- `rouge1_metrics_all_epochs.csv` (60KB)
- `rouge2_metrics_all_epochs.csv` (60KB)
- `rougeL_metrics_all_epochs.csv` (60KB)
- `rougeLsum_metrics_all_epochs.csv` (60KB)

**Structure:**
```
- sample_id: Sample identifier (0-99)
- epoch: Training epoch number (1-5)
- [rouge1|rouge2|rougeL|rougeLsum]: Specific ROUGE metric score
- instruction_preview: Question preview
```

**Purpose:** Track performance of specific ROUGE metric across all epochs
**Benefits:** 
- Easy comparison of single metric progression
- Simplified filtering and analysis
- Metric-specific trend analysis

### 3. Summary Report
**File:** `rouge_metrics_summary.csv` (441 bytes)

**Structure:**
```
- epoch: Training epoch (1-5)
- total_samples: Number of evaluated samples per epoch
- rouge1_mean: Average ROUGE-1 score
- rouge1_max: Maximum ROUGE-1 score
- rouge1_min: Minimum ROUGE-1 score
- rouge2_mean: Average ROUGE-2 score
- rouge2_max: Maximum ROUGE-2 score
- rouge2_min: Minimum ROUGE-2 score
- rougeL_mean: Average ROUGE-L score
- rougeL_max: Maximum ROUGE-L score
- rougeL_min: Minimum ROUGE-L score
- rougeLsum_mean: Average ROUGE-Lsum score
- rougeLsum_max: Maximum ROUGE-Lsum score
- rougeLsum_min: Minimum ROUGE-Lsum score
```

**Purpose:** High-level overview of epoch performance
**Use Case:** Quick comparison of metric trends across epochs

## Interpretation Guidelines

### Score Ranges
- **0.9 - 1.0:** Excellent similarity, near-perfect generation
- **0.7 - 0.9:** Good similarity, acceptable quality
- **0.5 - 0.7:** Moderate similarity, requires improvement
- **0.3 - 0.5:** Low similarity, significant differences
- **0.0 - 0.3:** Poor similarity, major differences

### Expected Behavior During Fine-Tuning
```
Pre-training (Baseline):
├── ROUGE scores vary widely (0.3-0.8 range typical)
│
Fine-tuning Progress:
├── Epoch 1: Scores improve by 5-15%
├── Epoch 2: Continued improvement, smaller gains
├── Epoch 3-5: Convergence, diminishing returns
│   └── Plateau indicates model saturation
│
Optimal Checkpoint:
└── Usually Epoch 3-4 (early stopping to prevent overfitting)
```

## Common Questions

**Q: Why are all baseline scores 1.0?**
A: The evaluation framework is currently using reference text as the hypothesis for validation. During actual fine-tuning, you'll replace this with model-generated predictions, which will have varying scores.

**Q: Which metric should I focus on?**
A: For medical text, prioritize ROUGE-L and ROUGE-Lsum as they better capture medical terminology accuracy. Use ROUGE-1/2 as secondary indicators.

**Q: How often should I evaluate?**
A: After each training epoch (recommended) or every N steps. More frequent evaluation provides better insight but increases computational cost.

**Q: What's a "good" ROUGE score for medical content?**
A: Aim for >0.65 average across all metrics. >0.75 is excellent for this domain.
