# TurkishMedLLM: Data Preprocessing Documentation

This document outlines the systematic preprocessing pipeline implemented for the TurkishMedLLM project, covering Data Ingestion, Cleaning, Transformation, and Chunking.

---

## 1. Data Ingestion Module
The first stage involves loading raw medical data from three distinct sources and standardizing them into a unified format.

### Intelligent Schema Detection
Datasets often use inconsistent column names (e.g., `soru` vs `question`). The module uses keyword-based heuristics to identify:
- **Question Columns**: `soru`, `question`, `input`, `instruction`, `prompt`, `hasta_sorusu`, etc.
- **Answer Columns**: `cevap`, `answer`, `output`, `response`, `completion`, `yanıt`, etc.
- **Fall-back Heuristic**: If no matches are found, the pipeline compares text columns and selects the shorter one as the question and the longer one as the answer.

### Dataset Selection Policy
To prevent double-counting and redundant data, the pipeline implements an automated ignore policy:
- **Source 1**: Prioritizes `train`/`test`/`validation` splits over the `FULL` file.
- **Source 2**: Prioritizes `Parquet` over `CSV` (Zenodo dataset).
- **Generic**: Automatically ignores non-data files like `README.md`, `.txt` sources, and system files.

### Quality Thresholding
Records are filtered out if they do not meet minimum length requirements:
- **Q&A**: Question ≥ 10 chars, Answer ≥ 30 chars, Combined ≥ 50 chars.
- **Articles**: Text ≥ 200 chars.

### Global Deduplication
Normalizes text and uses MD5 hashing to ensure every Q&A pair and article is globally unique across all source files.

---

## 2. Data Transformation Module
The second stage prepares the ingested data for Fine-tuning (SFT) and Retrieval-Augmented Generation (RAG).

### Text Cleaning & Normalization
- **HTML Removal**: Uses `BeautifulSoup` with the `lxml` parser to strip HTML tags and scripts while preserving text content.
- **Whitespace Normalization**: Collapses multiple spaces, tabs, and newlines into single spaces (or double newlines for paragraph breaks).
- **Turkish-Specific Care**: Preserves Turkish characters and medical abbreviations.

### SFT Instruction Formatting
Converts Q&A records into a standardized instruction-following format:
- **System Prompt**: *"Aşağıdaki tıbbi soruyu Türkçe olarak güvenli, anlaşılır ve klinik olarak dikkatli şekilde cevapla."*
- **Instruction**: The patient's question.
- **Response**: The professional medical answer.

### Recursive Character Text Splitting (RAG)
For the RAG corpus, articles are split into overlapping chunks to maintain context:
- **Chunk Size**: 1000 characters.
- **Chunk Overlap**: 150 characters.
- **Separators**: prioritized as `["\n\n", "\n", ". ", "? ", "! ", "; ", ", ", " ", ""]` to avoid splitting sentences or words.

### Chunk Quality Control
Post-split, fragments are filtered if:
- They are shorter than 100 characters.
- They contain less than 20% alphabetic characters (filtering out tables, noise, or code fragments).

---

## 3. Preprocessing Outputs
The pipeline produces the following standardized outputs in the `data-processed/` and `data-transformed/` directories:

| File Name | Purpose | Format |
| :--- | :--- | :--- |
| `turkishmedllm_qa_documents.jsonl` | Standardized unique Q&A pairs | JSONL |
| `turkishmedllm_sft_cleaned.jsonl` | Instruction-formatted data for SFT | JSONL |
| `turkishmedllm_article_chunks.jsonl` | Cleaned and split text for RAG | JSONL |
| `ingestion_report.json` | Detailed statistics on cleaning and policy | JSON |

## Execution Command
To run the full preprocessing suite:
```bash
# Step 1: Ingestion
python -m src.ingestion.ingestion_pipeline

# Step 2: Transformation
python -m src.transformation.transformation_pipeline
```
